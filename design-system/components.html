Design system

Components

Built on the token layer, with no hard-coded colour, size or spacing values. Each component lists the accessibility requirements that come with it — the guidance matters as much as the CSS, because a component is only accessible if it is used correctly.

Buttons

Sizes

Usage

  • One primary button per view. If everything is primary, nothing is.
  • Use <button> for actions and <a> for navigation. Never a div with a click handler.
  • Label with the action, not the confirmation — "Save patient", not "OK".
  • Danger variant is for destructive actions only, and should be paired with a confirmation step.
  • Targets grow to a 44px minimum on touch devices, per WCAG 2.5.5.

Form fields

The animal's name as it appears on the record.

In kilograms, to one decimal place.

✕ Enter a weight in kilograms, for example 4.2

Usage

  • Every input has a visible <label> tied to it by for/id. Placeholders are not labels — they vanish on typing and fail contrast.
  • Hints and errors are linked with aria-describedby so screen readers announce them with the field, not adrift from it.
  • Required is spelled out. An asterisk means nothing without a legend explaining it.
  • Errors are never signalled by colour alone — the border thickens and a message with an icon appears. This is WCAG 1.4.1.
  • Error text says how to fix the problem, not merely that one exists.

Checkboxes and radios

Alerts on file

Usage

  • Groups are wrapped in a <fieldset> with a <legend>, so the question is announced along with each option.
  • Radios for one choice from many; checkboxes for none, one or many.
  • The label is clickable, which widens the target well beyond the control itself.

Usage

  • role="status" announces politely, waiting for a pause. role="alert" interrupts — reserve it for genuine errors.
  • Each variant carries a distinct border and a title, so the meaning survives without colour perception.
  • Say what happened and what to do next.

Badges

Neutral Recalled Vaccinated Overdue Bite risk New

Usage

  • Badges are labels, not buttons. If it is clickable, it is a button or a link.
  • The word carries the meaning; colour only reinforces it.

Stepper

Used by the "before" version of the intake case study, where the wizard is the problem being demonstrated rather than the solution.

  1. Client
  2. Patient
  3. Complaint
  4. Vitals
  5. History
  6. Consent
  7. Review

Usage

  • Marked up as an ordered list, because the order is meaningful.
  • The current step carries aria-current="step".
  • Completed steps must be reachable. A stepper that only moves forward is the anti-pattern this case study exists to criticise.
